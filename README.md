# Data Hunter Platform (MVP)

Проект: платформа для сбора и обработки лидов из Яндекс Карт, 2ГИС и сайтов компаний, с последующей работой колл-центра и фиксацией статусов в CRM-подобной админке.

## 1) Цель MVP

Собрать быстрый и стабильный MVP, который:
- парсит карточки компаний из заданных источников;
- нормализует и дедуплицирует данные;
- предоставляет удобный UI для фильтрации и обработки контактов менеджерами;
- сохраняет историю звонков, статусы и комментарии;
- работает без высокой нагрузки, но с заделом на масштабирование.

## 2) Ключевые сущности данных

- **Company**: название, категория, адрес, гео-координаты, источник, url карточки.
- **Contact**: телефон, email, сайт, соцсети, ФИО (если есть), приоритет.
- **LegalInfo**: ИНН/ОГРН (если доступно), правовая форма.
- **LeadCard**: объединенный объект для оператора (все контакты и история).
- **CallTask**: назначение пачки лидов менеджеру.
- **CallLog**: время звонка, результат, комментарий, длительность, запись (опционально).
- **LeadStatus**: новый / в работе / недозвон / нецелевой / перезвон / успешно и т.д.
- **User**: роли `admin`, `manager`, `operator`.

## 3) Предлагаемая архитектура

### Backend
- `Python + FastAPI` для API и админ-логики.
- `PostgreSQL` как основная БД.
- `Redis` для очередей и кэша.
- `Celery`/`RQ` для фоновых задач парсинга и enrichment.

### Parser workers
- Отдельные воркеры по источникам:
  - Yandex Maps connector
  - 2GIS connector
  - Website scraper connector
- Пайплайн: `collect -> parse -> normalize -> deduplicate -> enrich -> persist`.

### Frontend
- `React + Next.js` (или `Vue + Nuxt`, на выбор после уточнения).
- Основные экраны:
  - Дашборд
  - Очередь лидов
  - Карточка лида
  - История звонков
  - Управление пользователями и ролями
  - Настройки источников и задач

### Call center модуль
- Минимально для MVP:
  - распределение лидов по менеджерам;
  - статусы звонка и комментарии;
  - фильтр «на перезвон»;
  - таймлайн активности по лиду.
- VoIP-интеграция на 2-м этапе (через SIP/провайдера), чтобы не перегружать 1-й релиз.

## 4) MVP scope (первый релиз)

1. Импорт целевых запросов и гео.
2. Парсинг из 1-2 источников (Yandex + сайты, 2GIS вторым шагом).
3. Базовая дедупликация (по телефону, сайту, названию + адресу).
4. Админка с базовыми ролями.
5. Экран менеджера для обработки лидов и выставления статусов.
6. Экспорт в CSV/XLSX.
7. Логи и мониторинг ошибок.

## 5) Нефункциональные требования (MVP)

- Скорость: асинхронные воркеры, батч-обработка.
- Качество: валидация телефонов/email, confidence score у контактов.
- Надежность: retry policy, anti-ban лимиты, прокси-пул (опционально).
- Безопасность: RBAC, аудит действий, хранение секретов через env.
- Поддерживаемость: модульная структура, документация API, тесты.

## 7) Риски и ограничения

- Ограничения источников (rate limits, anti-bot).
- Неоднородность данных с сайтов.

### Схема поиска контактов на сайтах (MVP)

Чтобы повысить качество сбора `телефон/email/адрес`, используем приоритетный обход страниц:
1. Главная страница: шапка (header), блок hero, подвал (footer).
2. Страницы: `Контакты`, `О компании`, `Реквизиты`, `Доставка/Оплата`.
3. Микроразметка и структурированные данные (`schema.org`, `Organization`, `LocalBusiness`).
4. Ссылки `tel:`, `mailto:`, блоки с реквизитами.

Правила качества:
- сначала берем наиболее надежные контакты (контакты/реквизиты),
- помечаем источник поля (header/footer/contacts-page),
- исключаем агрегаторы и страницы с нерелевантными ключевыми словами,
- при конфликте данных сохраняем несколько значений с приоритетом по достоверности.

Дополнительные риски:
- Юридические аспекты хранения персональных данных и звонков.
