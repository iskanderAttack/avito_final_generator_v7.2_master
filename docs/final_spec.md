# Финальное ТЗ (MVP): парсер + call-center админка

## 1. Цель релиза

Запустить MVP платформы для сбора и обработки лидов из Яндекс Карт, 2ГИС и сайтов с последующей обработкой менеджерами в встроенном call-center workflow.

**KPI релиза:**
- собрать 500–1000 лидов;
- обеспечить минимальный процент мусорных лидов за счет фильтрации и дедупликации;
- повысить конверсию обработки лидов за счет скриптов и SLA-перезвонов.

## 2. Функциональные требования

### 2.1 Парсинг и обработка данных
- Источники: Яндекс Карты, 2ГИС, сайты компаний.
- География: город, список городов, регион, вся РФ.
- Поля лида:
  - `name`, `category`, `address`, `phone`, `email`, `website`, `source`, `source_url`;
  - `inn`, `ogrn` при наличии.
- Валидация: формат телефонов/email.
- Фильтрация: исключение «мусорных» агрегаторов и нерелевантных страниц.
- Дедупликация:
  1) по телефону,
  2) по сайту,
  3) по нормализованным `name + address`.
- Скоринг (confidence score 0–100):
  - +40 за валидный телефон,
  - +20 за валидный email,
  - +20 за уникальный домен сайта,
  - +20 за совпадение категории и гео-фильтра.

### 2.2 Call-center модуль
- Менеджер получает ограниченный пакет лидов в работу.
- В карточке доступны:
  - данные контакта,
  - скрипт звонка,
  - история действий,
  - смена статуса и комментарий.
- Фиксация статусов (MVP):
  - `new`, `in_progress`, `no_answer`, `busy`, `callback_scheduled`,
  - `not_target`, `invalid_contact`, `interested`, `deal_created`, `closed_lost`.
- SLA/напоминания:
  - `no_answer` -> авто-задача перезвона через 4 часа;
  - `callback_scheduled` -> напоминание на заданное время;
  - `interested` -> контрольный follow-up в течение 24 часов.

### 2.3 Роли и доступ
- `admin`: пользователи, источники, статусы, системные настройки.
- `manager`: обработка лидов, статусы, комментарии, перезвоны.
- (phase-2) `operator`.

### 2.4 UI/UX
Обязательные экраны MVP:
1. Логин/регистрация.
2. Список лидов (фильтры, сортировка, поиск, пагинация).
3. Карточка лида + скрипт звонка + timeline.

Дополнительно:
- мобильная адаптация;
- русский язык интерфейса;
- простой светлый UI с акцентом на скорость обработки.

### 2.5 Интеграции и экспорт
- CRM-интеграции не включаем в MVP.
- Экспорт:
  - CSV/XLSX,
  - выгрузка в Google Sheets (через service account) — приоритетный канал.
- API-first: REST API для внешних подключений в будущем.

## 3. Нефункциональные требования
- Backend: Python + FastAPI.
- БД: PostgreSQL.
- Очереди: Redis + Celery.
- Деплой: Docker Compose.
- Нагрузка: умеренная, без high-load оптимизаций на старте.
- Аудит: лог действий пользователей + график активности.

## 4. Что НЕ входит в MVP
- VoIP/SIP интеграция и запись звонков.
- Антикапча/массовый прокси-пул.
- CRM двусторонняя синхронизация.
- Глубокая юридическая модель хранения ПДн.

## 5. Критерии приемки MVP
- Пилот запуска: успешная обработка первых 50 лидов (контроль качества и статусов).
- Получение 500–1000 лидов по заданным гео/нише после валидации пилота.
- Видимый эффект дедупликации (исключение дублей по ключевым полям).
- Менеджер может полностью обработать лид и поставить статус за <= 60 секунд.
- Работают напоминания по перезвонам.
- Экспорт данных в CSV/XLSX и Google Sheets.
